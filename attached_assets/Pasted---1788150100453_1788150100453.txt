كمّل على المشروع الحالي ولا تعيد بناء أي جزء من الصفر. عندي مشكلتين مهمين محتاجين إصلاح قبل اعتبار التطبيق جاهز:

1. مشكلة تحليل مراجعة الأسبوع — أولوية قصوى:
عند إنهاء مراجعة الأسبوع والضغط على "اعرض التحليل"، التطبيق يرجع:
"حصل خطأ في التحليل: HTTP 502 Bad Gateway: Failed to analyze the weekly review"

افحص الـ flow بالكامل من الـ frontend إلى الـ backend ثم Anthropic API وحدد السبب الحقيقي للـ 502، وليس مجرد إخفاء الخطأ أو إضافة retry بدون معرفة السبب.

تأكد من:
- أن الـ frontend يتصل بالـ endpoint الصحيح في الـ backend.
- أن الـ backend يعمل فعليًا ويمكن الوصول إليه.
- أن Anthropic API يتم استدعاؤه من الـ backend وليس من الـ frontend.
- أن `ANTHROPIC_API_KEY` يتم قراءته بشكل صحيح من Replit Secrets.
- أن اسم الموديل والإعدادات المستخدمة متوافقة مع Anthropic API الحالية.
- أن request body والـ headers والـ response parsing صحيحة.
- أن الـ backend يرجع errors مفهومة بدل HTTP 502 عام.
- تعامل بشكل صحيح مع أي timeout أو API error أو malformed response.
- اختبر التحليل فعليًا باستخدام بيانات مراجعة حقيقية، وتأكد أن التحليل يرجع ويظهر داخل التطبيق.

مهم جدًا:
لا تحذف أو تختصر نظام تحليل الأسبوع الحالي. الـ prompt والمحتوى والمنطق الخاص بتحليل الأهداف المبني على أفكار Stephen Covey مهم جدًا بالنسبة لي، وأريد الحفاظ عليه كما هو. أصلح فقط البنية التقنية التي تمنع التحليل من العمل.

2. مشكلة زر تغيير تاريخ نهاية الأسبوع:
زر "تغيير التاريخ" / "حدد التاريخ" يفتح date picker، لكن مربع الـ calendar يظهر في مكان غريب وبعيد عن الزر.

أصلح الـ date picker بحيث:
- يفتح بشكل طبيعي بجوار زر التاريخ أو في موضع مناسب بالنسبة له.
- يكون positioning صحيحًا على Desktop وMobile.
- لا يظهر بعيدًا عن العنصر بسبب overflow أو positioning أو أي container.
- لا يخرج خارج الشاشة على الموبايل.
- يحافظ على نفس وظيفة اختيار التاريخ الحالية.
- التاريخ المختار يظل محفوظًا ويظهر بشكل صحيح.
- يظل حساب "باقي X أيام" ومراجعة الأسبوع يعملان كما هما.

وبالنسبة لشكل الـ calendar:
اجعل تجربة اختيار التاريخ أنظف وألطف بصريًا، ومتناسقة مع Design System الحالي للتطبيق، بدون redesign للتطبيق كله.
لا تغيّر الهوية البصرية أو الألوان أو الـ typography أو النصوص الموجودة. فقط حسّن شكل وتجربة الـ date picker نفسه بما يتناسب مع التصميم الحالي.

قبل إنهاء المهمة:
- اختبر تحليل الأسبوع end-to-end وتأكد أنه يعمل فعلًا وليس فقط أن الكود لا يعطي errors.
- اختبر date picker على Desktop وعلى Mobile.
- اختبر اختيار تاريخ، تغييره مرة أخرى، وإعادة تحميل الصفحة.
- تأكد أن إصلاحاتك لم تكسر الحفظ أو المزامنة أو تسجيل الدخول أو PWA.
- إذا وجدت سببًا آخر يمنع التحليل من العمل، أصلحه بدل الاكتفاء بمعالجة رسالة 502.

بعد الانتهاء، أعطني ملخصًا واضحًا:
1. سبب خطأ HTTP 502 بالضبط.
2. ما الذي تم إصلاحه.
3. كيف اختبرت أن تحليل الأسبوع يعمل.
4. ما الذي تم تغييره في date picker.
